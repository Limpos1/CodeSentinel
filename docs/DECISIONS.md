# 설계 결정 기록

계획과 제안을 구분하며, 중요한 변경은 사용자 승인 후 결정으로 기록합니다.

## D-001: 프로젝트 범위와 스택

- 날짜: 2026-10-28
- 상태: 사용자 초기 지시로 정한 계획
- 내용: 공개 GitHub 저장소의 Java 코드를 Semgrep으로 분석하고 OpenAI API로 설명하는 웹서비스를 목표로 한다. Java 21, Spring Boot, Gradle, Thymeleaf, PostgreSQL, Docker를 사용한다.
- 이유: 사용자 프로젝트 목표와 학습·포트폴리오 방향을 따른다.
- 영향: 다른 스택이 필요하면 이유와 장단점을 설명하고 승인받는다. 세부 버전은 아직 미정이다.

## D-002: 문서부터 시작하는 단계별 개발

- 날짜: 2026-10-28
- 상태: 사용자 초기 지시에 따라 적용
- 내용: 현재 작업은 상태 확인과 초기 문서 6개 작성으로 제한한다. 기능과 빌드 구성은 생성하지 않는다.
- 이유: 초보자가 각 단계를 검토하고 여러 컴퓨터에서 문서와 코드 기준을 공유하기 위해서다.
- 영향: 이번 작업이 끝나면 멈추고 사용자 확인을 기다린다. Git 초기화, 커밋, 푸시, 병합, 배포는 수행하지 않는다.

## D-003: 외부 소스는 신뢰하지 않는 데이터

- 날짜: 2026-10-28
- 상태: 사용자 초기 보안 원칙으로 채택, 구현은 계획
- 내용: 공개 저장소만 지원하고 대상 코드를 실행하지 않는다. URL·자원·격리·비밀정보·AI 비용을 관리하며 AI 결과는 분석 의견으로 표시한다.
- 이유: 외부 입력으로 인한 서버 악용 및 운영 위험을 줄이기 위해서다.
- 영향: 구현 단계별로 구체적 정책과 테스트를 추가해야 한다. 문서 작성이 방어 구현을 뜻하지 않는다.

## D-004: 초기 문서 GitHub 공유

- 날짜: 2026-10-28
- 상태: 사용자 승인
- 내용: 초기 문서 작성 후 사용자가 바탕화면 이동과 GitHub 저장소의 첫 커밋·푸시를 승인했습니다.
- 이유: 다른 컴퓨터에서도 코드와 문서를 기준으로 이어서 작업하기 위해서입니다.
- 영향: D-002의 초기 작업 중단 이후 이번 작업 범위를 Git 초기화·원격 연결·문서 커밋·푸시로 확장합니다. 서비스 구현과 배포는 포함하지 않습니다.

- 프로젝트 group/package, Spring Boot 및 Gradle 버전
- 최소 의존성의 실제 구성
- 저장소 수집 방식과 자원 제한값
- Semgrep 실행 격리 방식과 규칙 세트
- 초기 작업 처리 방식과 타임아웃
- 데이터 접근·마이그레이션 도구 및 실제 스키마
- OpenAI 모델, 입력 최소화, 비용·실패 처리 정책
- 클라우드 환경과 운영·모니터링 방식

위 항목은 확정된 설계가 아닙니다. 제안, 이유, 장단점 및 필요한 사용자 승인을 후속 작업에서 기록합니다.
