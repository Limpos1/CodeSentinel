# 데이터베이스 구조

상태: 요구사항 정리 및 개념 모델 초안. PostgreSQL 연결, 테이블, 마이그레이션, ORM 엔티티는 없습니다. 아래 이름은 실제 스키마가 아닙니다.

## 저장 요구사항

- 분석 요청의 저장소 URL, 작업 상태, 시작·종료 시각 및 실패 정보
- 재현에 필요한 저장소 커밋 식별자, 분석 도구 및 규칙 버전
- Semgrep 탐지의 규칙 식별자, 심각도, 파일 경로, 위치 및 메시지
- 탐지와 연결된 AI 설명, 모델 식별자 및 사용량 정보

## 개념 모델 제안 — 확정 전

| 개념 | 주요 정보 | 관계 |
| --- | --- | --- |
| 분석 작업 | 식별자, 저장소, 커밋, 상태, 시간, 오류 | 탐지 결과 여러 개 |
| 탐지 결과 | 식별자, 규칙, 심각도, 파일·위치, 메시지 | 작업 하나에 속함 |
| AI 설명 | 원인, 개선 방향, 처리 상태, 모델, 사용량 | 탐지 결과에 연결하는 안 검토 |

작업 상태 예시: 대기, 수집 중, 정적 분석 중, AI 설명 중, 완료, 실패. 실제 상태명과 전이, 부분 성공 및 AI 실패 처리 정책은 설계 시 확정합니다. 현재 상태 머신은 구현되지 않았습니다.

## 미결정 사항

- 기본 키 유형, 테이블·컬럼 이름, 제약 조건 및 인덱스
- JPA 등 데이터 접근 방식과 마이그레이션 도구
- 트랜잭션 경계와 상태 갱신 방식
- 탐지 결과 단위 또는 묶음 단위 AI 설명 저장 방식
- 소스코드·코드 조각·원본 도구 출력의 저장 필요성 및 최소 보관 범위
- 보관 기간, 삭제 정책, 로그와 오류 메시지의 민감정보 제거
- AI 토큰·비용 추적과 사용자 없는 MVP의 요청 제한 방식

회원 및 사용자별 분석 이력 모델은 향후 확장 단계에서 추가합니다. 스키마 확정 시 이 문서와 마이그레이션·실제 코드를 일치시킵니다.
