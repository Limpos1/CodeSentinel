# 시스템 구조

상태: 목표 구조 초안. 아래 구성요소는 모두 미구현입니다.

## 목표 처리 흐름

```text
브라우저 (Thymeleaf 화면)
  → Spring Boot: 공개 GitHub URL 검증
  → 저장소 수집 및 자원 제한
  → Semgrep: Java 정적 분석
  → OpenAI API: 제한된 탐지 결과 설명
  → PostgreSQL: 작업 상태 및 결과 저장
  → 결과 대시보드
```

분석 상태는 처리 중에도 저장할 필요가 있습니다. 위 흐름은 기능 관계를 보여주며 DB 쓰기가 마지막에만 일어난다는 의미는 아닙니다.

## 역할별 분리 제안

| 영역 | 책임 |
| --- | --- |
| 웹 | 화면 표시, 요청 검증, 사용자 오류 안내 |
| 분석 조정 | 수집·정적 분석·AI 설명의 실행 순서와 실패 처리 |
| 저장소 수집 | 공개 여부 확인, 안전한 다운로드, 제한 및 정리 |
| 정적 분석 | 격리된 Semgrep 실행, 결과 파싱 |
| AI 설명 | 제한된 입력 전송, 설명 생성, 사용량 관리 |
| 저장 | 작업 상태, 탐지 결과, 설명 및 오류 기록 |

구체적 패키지 구조, 실행 방식, 외부 연동 인터페이스는 구현 단계에서 확정합니다. 비동기 작업과 알림은 향후 확장으로 두며, 초기 요청 처리 방식은 타임아웃과 사용성을 검토한 뒤 결정합니다.

## 구현 전 보안 검토

- URL: GitHub 호스트와 저장소 경로를 엄격하게 검증한다. 임의 호스트·포트·인증정보 입력을 차단하고 리다이렉트 및 실제 요청 대상도 검토한다.
- 공개 여부: 공개 저장소만 수집한다. 비공개 저장소 자격증명을 받지 않는다.
- 수집 방식: Git clone과 GitHub API/아카이브의 장단점을 비교하여 선택한다. 서브모듈, 심볼릭 링크, 압축 해제 경로 이탈 등의 위험을 고려한다.
- 실행 금지: 수집한 저장소의 빌드 스크립트, 테스트, 실행 파일 및 자체 분석 설정을 실행하지 않는다.
- 자원 제한: 다운로드·해제 후 크기, 파일 수, 개별 파일 크기, 전체 시간, 동시 작업 수를 제한한다. 수치와 초과 처리 방식은 미정이다.
- 분석 격리: Semgrep의 파일 접근·네트워크·CPU·메모리·실행 시간을 제한하는 환경을 검토한다. 서비스가 관리하는 규칙만 사용하도록 설계한다.
- 임시 파일: 작업별 디렉터리를 분리하고 실패·시간 초과 시에도 정리한다.
- AI: 소스 내용을 지시로 취급하지 않는다. 필요한 최소 코드만 전송하고 입력 길이·출력량·호출 수·비용·재시도를 제한한다.
- 표시: AI 결과와 저장소 텍스트는 HTML로 신뢰하지 않고 안전하게 표시한다. AI 설명은 검토가 필요한 의견으로 안내한다.
- 운영: 비밀정보는 외부 설정으로 주입한다. 로그의 코드·키 노출을 방지하고 저장 및 삭제 정책을 정한다.

현재 위 방어책의 구현·보안 검증은 수행하지 않았습니다.

## 단계

문서 초기화 → Spring Boot 기본 기동 → 기본 웹·URL 검증 → 저장소 수집 → Semgrep → AI → DB·결과 화면 → 테스트·Docker·배포. 각 단계에서 관련 문서를 갱신합니다.
